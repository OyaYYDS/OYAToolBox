# OYAToolBox 项目分析与重构方案

> 文档日期：2026-09-05
> 基线版本：c86a769（main 分支）
> 目的：在**不丢失现有功能**的前提下，解决「打包体积过大」与「运行卡顿」两大问题。

---

## 1. 项目概览

OYAToolBox 是一个 Windows 桌面工具箱启动器：把常用软件/脚本/文件夹/网址收纳到
一个带毛玻璃质感的无边框窗口中，支持网格/列表两种视图、图标自动提取、拖拽排序、
搜索、分类、使用统计等。

### 1.1 当前技术栈

| 层 | 技术 | 说明 |
|---|---|---|
| 壳层 | Python 3.10 + **PySide6 (Qt6)** | 无边框透明窗口、DWM 毛玻璃 |
| 页面 | **QtWebEngine**（内嵌 Chromium）+ QWebChannel | HTML/CSS/JS 前端，双向桥接 |
| 前端 | 原生 JS + CSS（8 个 JS 文件、3 个 CSS 文件，共约 3700 行） | 无任何前端框架 |
| 图标 | pywin32 + Pillow「双背景法」像素级还原 alpha | 每个图标一个后台线程 |
| 异步 | qasync（asyncio 事件循环） | 实际只用来跑 `loop.run_forever()` |
| 打包 | PyInstaller onedir + `collect_all('PySide6')` + Inno Setup 6 | `--collect-all PySide6` 收集**全量** PySide6 |

### 1.2 现有功能清单（重构后必须一一保留）

1. 网格视图 / 卡片（列表）视图切换；网格图标大小三档（小/中/大）
2. 卡片视图左右拖拽调整列表宽度、详情面板显隐
3. 添加/编辑/删除工具（名称、路径、描述、分类、标签、类型、启动参数、工作目录）
4. 图标三种模式：自动提取（exe/lnk/ico/文件夹/系统关联图标）、自定义图片、文字图标（可选颜色）
5. 拖拽排序（网格 + 卡片列表，鼠标事件实现，避免与 OS 级拖放冲突）
6. 右键菜单：启动 / 编辑 / 删除 / 打开所在位置 / 复制路径
7. 网格悬浮信息卡（延迟显示、锁定机制）
8. 实时搜索（名称/描述/路径/标签）；6 种排序方式
9. 分类栏筛选 + 分类管理（添加/删除）
10. 主题：深色 / 浅色 / 跟随系统（matchMedia 实时监听）
11. 窗口置顶；窗口位置/尺寸记忆
12. 多类型启动：exe / bat / cmd / ps1 / lnk / folder / url / 系统默认程序
13. 使用统计（次数、最近使用）；Toast 提示；空状态占位
14. OS 级文件拖入添加（拖入遮罩提示）
15. Windows 11 亚克力毛玻璃 + 圆角（Win10 回落 SetWindowCompositionAttribute）

## 2. 问题诊断

### 2.1 打包体积过大（"太厚重"）

**体积构成（按当前 `OYAToolBox.spec` + `build_exe.bat` 打包方式估算）：**

| 来源 | 贡献 | 说明 |
|---|---|---|
| Qt6WebEngineCore.dll + 资源 | ~250 MB | Chromium 内核本体，不可压缩 |
| `collect_all('PySide6')` 拖入的全量模块 | ~150–250 MB | **最大的人为浪费**，见下 |
| Qt 翻译文件（全语言） | ~10–20 MB | 实际只需要 zh-CN |
| pywin32 | ~15–25 MB | 仅用于图标提取，可被 ctypes 替代 |
| Pillow | ~4–5 MB | 仅用于 48×48 PNG 生成，可用 GDI+ 替代 |
| Python 运行时 | ~25–30 MB | 固定成本 |
| **onedir 合计估算** | **450–600 MB** | 安装包（lzma2 压缩后）约 180–250 MB |

**根因：**

1. **`collect_all('PySide6')` 是最大浪费**（spec 第 7 行 + `build_exe.bat` 的 `--collect-all PySide6`）。
   PyInstaller 本就会**按 import 自动收集** QtWebEngine 所需的全部依赖（hooks-contrib
   内置了完整的 PySide6 hook）。`collect_all` 反而把程序**从不 import** 的模块全部塞进去：
   Qt3D、QtCharts、QtMultimedia、QtPdf、QtSql、QtSensors、QtBluetooth、QtLocation、
   QtNfc、QtQuick3D、QtDesigner 等全部 `.pyd` + 全部 QML 目录 + 全部插件 + 全部语言翻译。
2. `upx=True` 写在 spec 里，但机器上没装 UPX 时 PyInstaller **静默跳过**，等于没开；且 UPX
   压 Qt DLL 易触发杀软误报，不建议作为主手段。
3. pywin32 + Pillow 只是给 `icon_extractor.py` 用的，功能可完全用 Windows 自带 API
   （shell32 + GDI+，纯 ctypes）替代，直接砍掉两个依赖。
4. qasync 整个依赖只为了 `loop.run_forever()`，Qt 自带事件循环足够，可删。

> 结论：**即使保留 PySide6 + QtWebEngine 不动，光修打包方式就能把 450–600 MB 降到
> 280–330 MB 左右**；但 QtWebEngine（Chromium）本体约 250 MB 的"地板"是这条路线的
> 硬下限——对"启动器"这类轻量工具而言依然厚重。

### 2.2 运行卡顿

按影响从大到小排列：

**根因 1：强制软件渲染（最大元凶）**
`main.py` 在 frozen 模式下强制了 `QT_OPENGL=software`、`AA_UseSoftwareOpenGL`、
`QTWEBENGINE_CHROMIUM_FLAGS = '--disable-gpu --no-sandbox'`。
这是当初为解决个别机器白屏做的"核武器"式处理——代价是整个 Chromium 页面**全部用 CPU
软渲染**。CSS 阴影、动画、滚动、hover 全部变成 CPU 光栅化，卡顿几乎必然。
（白屏的真正诱因更可能是 conda 的 ICU DLL 冲突——main.py 开头的 PATH 过滤已经修了这个问题，
GPU 可以被安全放回。）

**根因 2：窗口拖动/缩放逐帧走 JS → Python 桥接**
`web/js/drag_handler.js` 的 `WindowDrag`/`WindowResize` 在每个 `mousemove`
（每秒 60–125 次）里调 `window.AppBridge.moveWindow(dx,dy)` / `resizeWindow(w,h)`。
每次调用 = 一条 QWebChannel 异步消息 → Qt 事件队列 → `self.move()/resize()` → **整个
WebEngine 页面重绘**。叠加根因 1 的软件渲染，拖动窗口就是最直观的卡顿场景。
正确做法：mousedown 时调用一次 Qt 原生的 `windowHandle().startSystemMove()` /
`startSystemResize()`，之后由操作系统接管，零桥接零卡顿。

**根因 3：透明窗口 + backdrop-filter 组合**
`main.css` 中 `#titlebar` 有 `backdrop-filter: blur(8px)`、`.modal-overlay` 有
`blur(4px)`。backdrop-filter 本身就是 Chromium 中开销最大的 CSS 属性之一，再叠加
`WA_TranslucentBackground` 透明窗口合成路径（软件渲染下更慢），是滚动/弹窗卡顿的直接来源。
（窗口已有 DWM 亚克力毛玻璃，CSS 层的 backdrop-filter 属于重复工作，可直接移除。）

**根因 4：全量 DOM 重建 + 逐项入场动画 + 搜索无防抖**
- `app.js` 搜索框 `input` 事件**无防抖**，每敲一个字 `_renderTools()` 就全量重建；
- `grid_view.js`/`card_view.js` 每次 render 都 `innerHTML = ''` 后重建全部条目；
- 每个网格项都带 `anim-fade-in` 动画类——批量渲染时 N 个动画同时跑（软件渲染下雪上加霜）。

**根因 5：图标 base64 每次渲染都要解码、且多视图重复嵌入**
图标以 `data:image/png;base64,...` 内联进 innerHTML，网格/卡片/悬浮卡/详情四处各嵌一份。
每次搜索、切换视图都重新解码全部图标 PNG。正确做法：图标提取一次后**缓存为磁盘文件**，
用 `file://` URL 引用（浏览器有图片缓存，重复渲染零成本）。

**根因 6：每个图标一个线程 + 50ms 常驻定时器**
`bridge.py` 的 `requestIcon` 每调用一次 `threading.Thread(...).start()`——启动时 N 个工具
同时开 N 个线程；`_icon_timer` 以 50ms 间隔**永远空转**（20 次/秒）。且
`icon_extractor.py` 的「双背景法」在纯 Python 里对 48×48 像素做逐像素双层循环，
单个图标 CPU 开销不小。应改为固定 2–4 线程池 + 事件驱动的结果分发。

**根因 7：resize 过程中反复重应用 DWM 属性**
`window.py` 的 `_on_resize` 每次 resize 事件后 `QTimer.singleShot(50, _apply_dwm_effect)`，
连续拖拽缩放时反复调用 `DwmExtendFrameIntoClientArea`，引起额外闪烁与重绘。应在
鼠标松开（缩放结束）时应用一次。

**根因 8：qasync 冗余**
所有桥接方法都是同步的，asyncio 循环只增加了启动开销和复杂度，无任何收益。

## 3. 技术路线对比

| 维度 | **方案 A：保留 PySide6+QtWebEngine，深度精简** | **方案 B：纯 QtWidgets 重写** | **方案 C：pywebview + WebView2（推荐）** |
|---|---|---|---|
| onedir 体积（估算） | 280–330 MB | 70–110 MB | **40–60 MB** |
| 安装包（lzma2） | ~110–140 MB | ~30–45 MB | **~20–30 MB** |
| 体积硬下限 | QtWebEngine ~250 MB 地板 | 最低 | WebView2 由系统提供，无需打包 |
| 卡顿解决程度 | 中：需逐项修（GPU 恢复、原生拖拽、渲染优化） | 彻底：原生控件 | **彻底：Edge Chromium 硬件加速 + 系统级原生拖拽/缩放** |
| 前端代码保留 | 100%（仍需 JS 层优化） | 0%（全部重写为 Qt 控件/QSS，毛玻璃质感与悬浮卡等交互实现成本高） | **~95%**（仅重写 bridge.js、删除窗口拖拽 JS） |
| Python 改动 | 中（去 qasync/pywin32/Pillow、原生拖拽、打包 spec 重写） | 大（全部 UI 重写） | 中（bridge→js_api、图标 ctypes 重写、打包 spec 重写） |
| 新依赖 | 无 | 无 | pythonnet（.NET，Win10/11 内置）；WebView2 Runtime（Win11 预装，Win10 附引导程序 ~2MB） |
| 主要风险 | ① 体积仍 ≥300MB，未必满足"轻薄"预期；② 重新启用 GPU 后个别老机器可能复现白屏（需留降级开关） | UI 细节/手感很难 100% 对齐现有 Web 版；工作量最大 | ① OS 文件拖入需 WinForms 层钩子（或用浏览按钮替代）；② 亚克力毛玻璃需按窗口标题定位 HWND（或降级为纯色圆角窗口）；③ pywebview 打包需按官方指南配置 pythonnet |

**推荐：方案 C**。理由：
- 两个核心诉求（体积、流畅）都能一步到位——WebView2 复用系统 Edge 内核（零打包）、
  默认硬件加速（卡顿根源 1 直接消失）、无边框窗口拖动/缩放由系统接管（根源 2 直接消失）；
- 前端 3700 行 JS/CSS 是项目最大的资产，方案 C 几乎原样保留；
- 唯一需要认真处理的第三方依赖 pythonnet + WebView2 Runtime 在 Win10/11 上均有内置或官方引导程序兜底。

若坚持留在 PySide6 生态，**方案 A 是稳妥退路**（体积仍能减半、卡顿可大幅缓解，但有
~300MB 的硬地板）。方案 B 性价比最低，不推荐。

## 4. 方案 C 详细设计（pywebview + WebView2）

### 4.1 目标架构

```
┌─────────────────────────────────────────────────────────────┐
│ main.py            pywebview.start()  frameless + easy_drag │
│ app/api.py         所有桥接方法 → js_api（同步返回 JSON）      │
│ app/data_manager.py   保留 + 数据目录修复 + 原子写入            │
│ app/tool_launcher.py  基本保留                                 │
│ app/icon_extractor.py 重写：ctypes + shell32 + GDI+（删 pywin32/Pillow）
│ app/win_effects.py    DWM 圆角/亚克力（ctypes，按窗口标题定位 HWND）
│ web/                前端保留，仅 bridge.js 重写、drag 原生化    │
└─────────────────────────────────────────────────────────────┘
        ▲ JS: await pywebview.api.xxx(...)    ▼ Python: window.evaluate_js(...) 推送
```

### 4.2 Python 层

**`app/api.py`（替代 bridge.py）**：方法签名与现有 Bridge 槽一一对应
（getTools/addTool/updateTool/deleteTool/reorderTools/launchTool/getSettings/
saveSettings/getCategories/addCategory/deleteCategory/openFileDialog/detectFileType/
openFileLocation/copyPath/getFileInfo），全部同步返回 JSON 字符串；js_api 调用是
直连回调（比 QWebChannel 消息队列快得多）。图标异步结果用
`window.evaluate_js('AppBridge.onIconLoaded(...)')` 从线程池推回。

**`app/icon_extractor.py`（重写）**：
- exe/dll/scr/ico：`shell32.ExtractIconExW` 提取真实图标（无需 shell token，兼容性最好）；
- `.lnk`：pythonnet `WScript.Shell` 解析目标后递归取目标图标（不再需要 win32com）；
- 文件夹/系统关联图标：`SHGetFileInfoW`（优先真实图标，失败回退 `USEFILEATTRIBUTES` 属性法）；
- `gdiplus.GdipCreateBitmapFromHICON` 直接拿到带 alpha 的位图（**不再需要双背景像素循环**），
  `GdipSaveImageToFile` 编码 PNG，全程纯 ctypes；
- 文字图标改为**前端直接渲染**（现有 `.text-icon` CSS 类即可），Python 不再生成；
- 固定 3 线程池（`concurrent.futures`），替代"每图标一线程"；
- 提取结果（PNG bytes）缓存到 `%LOCALAPPDATA%\OYAToolBox\icons\<hash>.png`（按 路径+mtime 缓存），
  以 data URI 推送给前端——*实现偏差*：pywebview 默认以 http://127.0.0.1 提供页面，跨源引用
  `file://` 图片会被 Chromium 拦截，故改用 data URI（提取有磁盘缓存、GPU 解码开销可忽略）；
- 依赖表：**删除 pywin32、pywin32-ctypes、Pillow**。

**`app/data_manager.py`（修复）**：
- 数据目录改为「exe 同目录 `data/`（便携优先）→ 不可写时回退 `%APPDATA%\OYAToolBox`」；
- JSON 写入改为 tmp 文件 + `os.replace` 原子写，防止写一半崩溃损坏数据；
- 保留全部现有字段与默认值（含 categories 等）。

**`app/win_effects.py`（新增）**：把 window.py 里现成的 DWM 亚克力/圆角 ctypes 代码迁过来
（无需 pywin32）；窗口句柄通过 `EnumWindows` 按唯一窗口标题定位。若个别环境不稳定，
**降级方案：不透明圆角窗口**（外观由 CSS 保证，DWM 亚克力作为可选增强）。

**窗口行为（全部原生，删掉 JS 拖拽实现）**：
- `frameless=True, easy_drag=True` → 标题栏拖动由系统接管；
- 无边框窗口自带边缘缩放（`resizable=True`），`min_size=(800,500)` 统一约束；
- 置顶 `window.on_top`、最小化 `window.minimize()` 直接走原生 API；
- 窗口关闭前把 x/y/width/height 存回 settings（沿用现有字段）。

### 4.3 前端层（改动最小化）

| 文件 | 改动 |
|---|---|
| `index.html` | 删 `qwebchannel.js` 的 `<script>` 行；修复图标文字组双重 display（问题 4） |
| `js/bridge.js` | 重写：`window.AppBridge = window.pywebview.api` 的 Promise 封装（方法名全部不变，其余 JS 文件零改动） |
| `js/drag_handler.js` | 删除 `WindowDrag`/`WindowResize` 两个模块（原生接管）；**保留 DragSort** 工具项排序 |
| `js/app.js` | 搜索输入加 120ms 防抖；删除确认改为自绘确认框（若走 WebView2 可保留 confirm，二选一）；图标缓存复用逻辑 |
| `js/grid_view.js` / `js/card_view.js` | 批量渲染时去掉逐项 `anim-fade-in`（仅首次挂载/单条新增时保留）；图标 `<img src>` 改用磁盘缓存 URL |
| `css/main.css` | 移除两处 `backdrop-filter`（#titlebar、.modal-overlay）；其余主题/动画保留 |
| 其余 CSS/JS | 不动 |

### 4.4 打包

- `requirements.txt` → `pywebview>=5.0`（其依赖自动带上 pythonnet），删除 PySide6/qasync/pywin32/Pillow；
- `build_exe.bat` / `.spec` 重写：按 pywebview 官方 PyInstaller 指南收集 `clr`（pythonnet）
  与 `WebView2Loader.dll`；datas 只加 `web` 与图标文件；**data/ 不再打包进程序目录**
  （首次运行自动生成到用户数据目录）；
- Inno 脚本小改：`[Files]` 附带 WebView2 Evergreen 引导程序（`MicrosoftEdgeWebview2Setup.exe`，
  ~2MB），`[Run]` 检测已安装则跳过（静默安装）；
- 预期：onedir ≈ **40–60 MB**，安装包 ≈ **20–30 MB**（约为现状的 1/10–1/8）。

### 4.5 预期性能收益

| 场景 | 现状 | 重构后 |
|---|---|---|
| 启动速度 | 需加载数百 MB Qt DLL + 软件渲染初始化 | 只加载 ~50MB；WebView2 进程由系统预热 |
| 拖动窗口 | 每帧 JS→Python 消息 + 全页软件重绘 | **系统原生拖动，零桥接** |
| 搜索输入 | 每键全量重建 + 全部图标解码 + N 项动画 | 120ms 防抖 + 图标文件缓存，仅文本更新 |
| 滚动/弹窗 | backdrop-filter + 软渲染 | 硬件加速、无 backdrop-filter |

## 8. 风险与回退

## 附 2：验收阶段修复记录（2026-09-05 ~ 09-06）

按用户实测反馈修复的问题：

1. **窗口尺寸漂移变小**：pywebview WinForms 坑——先带边框设 Size 再切无边框，外框被缩掉边框尺寸。
   `shown` 时按目标几何 `SetWindowPos` 强制校正；关闭时用 `GetWindowRect` 保存真实外框；
2. **无法拉伸窗口**：pywebview frameless 无边缘缩放。WM_NCHITTEST 子类化返回边缘码 +
   WM_NCLBUTTONDOWN 直达 DefWindowProc（WinForms 会吞消息）；实测该路径未接管时由
   JS 直接调 `setWindowRect`（位置+尺寸联动, 各边缘锚点正确, 最小 800×500）；
3. **圆角白角**：`transparent=True` 只透明了 WebView2 背景, WinForms 窗体白底透出。
   改不透明 + 页面 html/body 填主题底色 + 启动时按系统主题解析窗口底色防闪白；
4. **初始尺寸改为 800×600**；列表视图**分栏改为比例制**（`card_list_ratio`，进入列表视图
   固定正中间、窗口缩放按比例联动、拖中框实时换算比例）；
5. **图标模糊**：32px 小图标硬放大所致，改用 `PrivateExtractIconsW` 按 48px 精确提取
   （IImageList/SHGetImageList JUMBO 方案因系统图像列表 vtable 不兼容已弃用），缓存版本 v3；
6. **隐藏详情后无法恢复**：CSS 连按钮一起隐藏，改为只收起内容保留"显示详情"按钮；
7. **网格视图悬浮信息卡固定改为左键**（原为右键），右键仅弹菜单。
